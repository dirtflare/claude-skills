# PIXAGAVE 設計書

「実物の写真をドット絵に変換し、**実際の育成が進んだ分だけ**キャラクターが進化する」を中核に据えた
アガベ/塊根/多肉の育成管理アプリ。バックエンドなし、依存パッケージなしの Web アプリとして実装している。

---

## 1. 立ち位置についての明記

参照元として提示された AGAVEDEX は App Store / Google Play で配信中の商用アプリであるため、
**画像・コード・ブランド・画面デザインの複製は行っていない**。本実装は

- 「写真 → ピクセル化」
- 「実際の育成の進捗でキャラクターが進化する」
- 「品種図鑑 / 個体アルバム / ケア記録の社群比較 / 共有画像生成」

という**機能の構成**を継承したうえで、アルゴリズム・データ・UI・世界観をすべて独自に設計したもの。
品種データと栽培の目安は一般的な園芸情報に基づく簡易モデルであり、実際の栽培判断の代替にはならない。

## 3. 中核システム

### 3.1 写真 → ドット絵 (`pixelize.js`)

```
正方形クロップ(160px)
  → 外周リングから背景色を推定
  → 背景距離 + 彩度 + 色相差 + 「植物寄りの色相帯」でマスク生成
  → モルフォロジー(膨張→収縮×2→膨張)でノイズ除去
  → 中央寄りを優遇した最大連結成分の抽出 + 穴埋め
  → 外接矩形を正方形化して N×N へ縮小(マスク加重平均。背景色の混入を防ぐ)
  → k-means で減色(既定 8 色)
  → HSL 量子化でスタイライズ(彩度 ×1.22 / 明度 9 段 / 品種の基調色相へ 14% 寄せる)
  → Bayer 4×4 ディザ
  → 左上光源の擬似ライティング + 1px 輪郭
  → PNG
```

抽出に失敗した場合(マスクが画面の 4.5% 未満 or 97% 超)は中央円にフォールバックする。

**個性値の抽出**もこの段階で行う。写真そのものから測るのがこの実装の肝で、

| 個性値 | 測り方 |
|---|---|
| 葉幅 | 行ごとの被覆長の平均 |
| 締まり | 外接正方形に対する充填率 |
| 棘 | 面積あたりの輪郭長(ギザギザさ) |
| 斑 | 平均輝度 +1.05σ を超える有彩色画素の比率 |
| 白粉 | 高明度・低彩度の画素比率 |
| 成長力 | 平均彩度と充填率の合成 |

最終値は `写真の解析値 × 0.55 + 品種バイアス × 0.45 + 揺らぎ` 。
2 枚目以降の写真では既存値へ 22% だけ寄せるので、実物が変われば少しずつキャラクターも変わる。

### 3.2 育成シミュレーション (`game.js: tick`)

実時間ベース。1 分ごと + タブ復帰時 + 起動時に経過分をまとめて反映する(オフライン進行あり)。

- **水分**: 品種の適正間隔で 100 → 0。日照設定が高いほど早く乾く。休眠期は 45% に減速
- **養分**: 一定速度で減少
- **害虫**: 過湿 ×1.6 / 弱日照 ×1.9 で増加。遮光ネット所持で軽減
- **健康**: 水分帯・日照差・害虫・養分から目標値を作り、そこへ緩やかに収束
- **個性値のドリフト**: 下記

### 3.3 「育て方が姿に出る」個性値ドリフト

毎ティック、初期値 ±26 の範囲で個性値が動く。ここが育成の手応えの中心。

| 条件 | 効果 |
|---|---|
| 適正日照 ±8 かつ乾かし気味 | 締まり +0.9/日 |
| 適正日照 −18 未満(弱光) | 締まり −1.1/日(徒長) |
| 適正日照付近で健康 55 超 | 棘 +0.35/日 |
| 養分 55 超・水分 35 超 | 成長力 +0.55 / 葉幅 +0.3 |
| 養分 15 未満 | 成長力 −0.4 |
| 乾燥 + 強光 | 白粉 +0.3 |
| 害虫 45 超を放置 | 葉幅 −0.5 / 締まり −0.35 |

### 3.4 進化(全 5 段階)

実生 → 幼苗 → 若株 → 成株 → 完成株。条件は **AND**。

| 段階 | 経験値 | 経過日数 | 記録写真 | 実測の伸び |
|---|---|---|---|---|
| 幼苗 | 120 | 3 日 | 2 枚 | — |
| 若株 | 420 | 14 日 | 4 枚 | +3cm |
| 成株 | 1,000 | 45 日 | 7 枚 | +8cm |
| 完成株 | 2,200 | 120 日 | 12 枚 | +15cm |

加えて **健康 55 以上**、かつ **休眠期でないこと**。
実測を入れていない場合は「記録写真 +2 枚」で代替できる(実測を入れたほうが早い設計)。

経験値は、適正タイミングの潅水 +16 / 早すぎる潅水 +2 / 写真 +25 / 実測 +15+伸び×12 / 品評会優勝 +60〜 で入る。
**時間経過だけでは上がりきらない**ようにして、実際に世話をした人が先に進む設計にしている。

### 3.5 分岐進化(4 系統)

成株到達時に、個性値と「初期値からどれだけ伸ばしたか」で系統が確定する。

| 系統 | 決まる条件 | 性格 |
|---|---|---|
| 締型 | 締まりを伸ばした + 管理スコア 70 超 | 強光・辛い水やりで葉間を詰めた姿 |
| 錦 | 斑・白粉が高い | 斑が覚醒。日焼けに弱い |
| 鬼爪 | 棘を伸ばした | 鋸歯が過剰発達 |
| 巨大 | 成長力・葉幅・実測サイズが大きい | 体積で押す |

成株になる前は「系統の傾き」が %で可視化され、**育て方で誘導できる**。
同じ品種でも育て方を変えれば別系統になるため、図鑑のコンプリート要素として機能する。

### 3.6 季節

実際の月から春夏秋冬を判定し、成長係数を掛ける。夏型(アガベ・多くの多肉)は冬に、
冬型(亀甲竜・リトープス)は真夏に休眠する。**休眠中は進化しない**。
「今すぐ進化させたいから」ではなく「株のリズムに合わせて待つ」という現実の栽培感覚をゲーム側に持ち込むための仕組み。

## 4. 参照元にない独自要素

1. **個性値が写真そのものから決まる** — 同じ品種でも、実際の株の姿でステータスが変わる
2. **個性値ドリフト** — 日照設定と潅水の癖が、そのままキャラクターの姿に蓄積される
3. **系統の傾きメーター** — 分岐先が事前に見え、狙って誘導できる
4. **季節・休眠システム** — 実際の栽培カレンダーと同期
5. **品評会リーグ**(棚デビュー → 世界選手権) — 姿 / 気迫 / 色 / 貫禄 / **管理** の 5 部門審査。
   管理部門は潅水間隔の安定性など実際の記録から算出されるので、記録を残す動機になる
6. **交配ラボ** — 成株 2 株から実生を作る。約 20% で突然変異(斑の覚醒・巨大化・極端な矮性)
7. **棚メイトの所見** — 状態からルールベースで助言を出す
8. **成長ストリップの書き出し** — アルバムを DAY 表記付きの 1 枚絵にする
9. **タイムワープ** — 進化条件が最大 120 日を要求するため、体験・デモ用に時間を進められる

## 5. データとプライバシー

- 写真・ドット絵は **IndexedDB**、ゲーム状態は **localStorage**。外部送信は一切ない
- IndexedDB が使えない環境ではメモリにフォールバックする
- 設定画面から状態＋画像を 1 つの JSON にまとめて書き出し／読み込みできる
- コミュニティ統計はサーバを持たないため、品種 ID と週番号から決定論的に生成した**推定コホート**。
  UI 上でも「推定値」であることを明示している

## 7. 今後の拡張案

- **PWA 化**(オフライン起動・ホーム画面追加・カメラ起動の最適化)
- **定点撮影ガイド** — 前回の写真を半透明で重ねて構図を揃え、比較精度を上げる
- **本物のコミュニティ** — 匿名の集計値だけを送るオプトイン方式にすれば、推定コホートを実データに置換できる
- **AR 風の実寸計測** — 鉢の直径を基準にして写真から株幅を自動推定
- **系統の追加** — 綴化(クレスト)・子株王・徒長からの復活など、失敗も個性になる系統
- **棚(シェルフ)ビュー** — 全個体を 1 枚のドット絵の棚に並べて眺める
