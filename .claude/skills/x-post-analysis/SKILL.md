# X 記事解析スキル

X の投稿を「取得 → 抽出 → 検証 → 構造化」する運用手順。
スキルは取得エンジンではなく指示書である:
取得手段(Web取得・ブラウザ・画像理解)を状況に応じて切り替え、
LLM が意味を解析し、定めた形式で出力する。

**このスキルは特定のアプリやリポジトリに紐付かない。**
解析結果をどこかに保存・反映するのは、ユーザーが明示的に
出力先(設計書、ワークフロー、メモ、コード等)を指定した場合だけ。
指定が無ければチャットでの報告が成果物である。

## Step 1 — URL の種類を判定

- `x.com` / `twitter.com` の status URL → 投稿本体
- プロフィール URL → 投稿の特定が必要。どの投稿か確認する
- 短縮 URL (`t.co`) → 展開を試みてから判定

## Step 2 — 取得手段を順に試す

上から順に試し、成功した時点で Step 3 へ。

1. **Web 取得** — WebFetch を本体 URL に 1 回。
2. **ミラー API** — `api.fxtwitter.com/<user>/status/<id>` に 1 回。
3. **ブラウザ操作** — この環境には Chromium + Playwright がある
   (`/opt/pw-browsers/chromium`)。JS レンダリングが原因で 1–2 が失敗した
   場合に有効。ページを開き、「さらに表示」展開・スクロールで
   スレッドを読み、必要ならスクリーンショットを撮って自分で読む。
4. **ユーザー提供素材** — 1–3 が失敗したら、失敗の理由を一言で伝え、
   次のいずれか **1 つ** を依頼する(全部は求めない):
   - **スクリーンショット添付**(最も確実。画像は直接読める。
     スレッドが長い場合は複数枚可)
   - **ページ丸ごとコピペ**(全選択→コピー→貼り付け。整形不要)
   - 動画の場合: 字幕・文字起こし・NotebookLM まとめ等、手元にある要約

**ネットワークポリシーへの注意:** リモート実行環境では x.com への接続が
環境のネットワークポリシーで遮断されていることがある(接続前 403 =
プロキシのポリシー拒否)。その場合 1–3 は全て失敗する。原因を
「モデルの制限」ではなく環境設定として正確に伝え、恒久対応として
claude.ai/code の環境設定でネットワークポリシーを緩和(x.com 等を許可)
できることを案内する。当面の解析はスクリーンショット添付で進める。

## Step 3 — 抽出(本文・スレッド・画像・動画を分離)

取得したものが HTML でも、乱雑なコピペでも、スクリーンショットでも、
同じものを抽出する:

- **投稿者**: 表示名、@ハンドル、認証マーク
- **本文**: スレッドは順序を復元。引用ポスト・返信は本体と区別する
- **日時・エンゲージメント**(読み取れれば)
- **画像**: 掲載された図、ストーリーボード、プロンプト例、UI 画面、
  複数画像の順序と関係
- **動画**: 本文・代表フレーム・字幕・文字起こし・提供された要約から
  分かる範囲を再構成。**動画自体を見ていない場合はその旨を必ず明記**
- **外部リンク**: 展開して中身も確認する価値があるか判定

UI ノイズ(返信/リポスト/いいね等のラベル、カウント、「さらに表示」、
プロモーション投稿)は除去する。迷ったら削らず「要確認」として残す。

## Step 4 — 検証(主張と事実を分ける)

1. 投稿者の**主張**と**確認可能な事実**を分離する
2. 製品仕様・API・リリース・統計は**公式情報**(公式ドキュメント、
   GitHub、一次ソース)で照合する。X 自体は検索でも読めないことが
   多いので、一次ソースを直接当たる
3. 時点依存の情報(料金、機能、制限)は取得日を添える
4. 確認できないものは推測で埋めず「**確認不能**」として残す
5. 宣伝・誇張の兆候(アフィリエイト、釣り文句)があれば指摘する

## Step 5 — 構造化して出力

既定の報告形式:

```
## 要約
(投稿者 / 日時 / 何についての投稿か、2〜3 文)

## 内容の構造化
(手順・プロンプト・設計など、投稿が伝えている中身を再利用できる形で)

## 主張と検証結果
(✅公式情報と一致 / ⚠️確認不能 / ❌誤り、それぞれ根拠付き)

## メリット / リスク
(この内容を採用する場合の利点と注意点)

## 確認不能だった点
(取得できなかった部分、動画未視聴など。無ければ省略)
```

ユーザーが出力先を指定した場合(設計書にして、ワークフローに変換して、
○○リポジトリに取り込んで等)は、この構造化結果を基にその形式へ変換する。
指定が無い限り、ファイルやコードへの保存・反映は行わない。
