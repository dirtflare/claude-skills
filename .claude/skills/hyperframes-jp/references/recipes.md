# 実践レシピ 5選

前提: **`frame.md` を置いたフォルダで実行する** (→ [brand.md](brand.md))。
そして**必ず `/hyperframes` から入る**。以下のプロンプトはワークフロー名を
直接書いているが、迷ったら `/hyperframes` に丸投げすればルーターが振り分ける。

---

## レシピ1: テーマを渡すだけで解説動画が完成する

**`/faceless-explainer`** — 顔出しなし、撮影なし、素材なし。
渡すのはテーマだけ。リサーチ、台本、ナレーション音声、動くタイポグラフィ、
図解、字幕、BGM、効果音、レンダリングまで全部やる。

一番出番が多くなるレシピ。**自分の note や X の内容を動画化するのが鉄板。**

```
/faceless-explainer を使って45秒の解説動画を作ってください。
テーマは「ここに記事の主張や手順を貼る」です。
内容に関わる数字や固有名詞は、Web検索で事実確認をしてから使ってください。
ナレーションは日本語で、デザインは frame.md に従ってください。
```

- 尺は45秒に限らず 60秒でも 90秒でも指定できる。
  **最初のうちは短めの方が修正の練習がしやすい**
- 「事実確認をしてから使ってください」の一文は入れておく。
  適当な数字で動画を作って後から燃える事故を構造的に避けられる
- 1つのテーマから記事・ポスト・動画の3展開ができる。
  ストック型の発信をしてきた人ほど恩恵が大きい

⚠️ ナレーションには HeyGen へのサインインが要る (`npx hyperframes auth login`)。
無料枠で回る。Kokoro はサインインしない場合のローカル代替にすぎない
(→ [setup.md](setup.md))。

## レシピ2: 曲を渡すと音ハメ動画になる

**`/music-to-video`** — 音楽ファイルを渡すとビートに同期した動画になる。
エージェントは先に曲を解析して BPM・拍の位置・盛り上がりの構造・
ドラムのフィルの場所まで読み取った設計図を作り、**すべてのカットをそれに従わせる。**

```
/music-to-video で、この曲から30秒の告知動画を作ってください。
内容は「告知したい商品やイベントの情報」です。
すべてのカットはビートに同期させて、
一番の見せ場は曲の盛り上がりに合わせてください。
デザインは frame.md に従ってください。
```

- 商品ローンチの予告、イベント告知、月次の振り返りと相性がいい
- **BGM 選びのセンスがそのまま動画の質になる。** 音源だけはこだわって選ぶ
- 音楽的なセンスに自信がない人ほど機械に任せる価値がある
- 修正しても同期は崩れない。カットは近くのドラムの音へ吸着し直され、
  全体の尺まで整えて返ってくる

## レシピ3: 数字1個がモーショングラフィックスになる

**`/motion-graphics`** — 10秒以下の短尺特化。ナレーションなし、
**動きそのものがメッセージ。** 数字のカウントアップ、グラフのアニメーション、
ロゴの登場演出、テキストカード。

**入力のハードルが最も低い。最初の1本はこれが最短。**

```
/motion-graphics で5秒の実績カードを作ってください。
「フォロワー10,000人達成」の数字が0からカウントアップして、
達成日をカードの下に小さく入れてください。
デザインは frame.md に従ってください。
```

- **コツはひとつ: エフェクト名を指定しない。**
  「ズームで」「バウンドさせて」は言わなくていい。
  伝えたい内容と見せたい順番だけ言えば、動きのデザインはエージェントが決める
- **背景を透明にして書き出せる。** 手持ちの動画に重ねる素材として使える
- 日付や出典を画面の隅に入れると数字の透明性が上がり、
  実績報告の信頼感がワンランク変わる
- 週に1枚この手のカードを出すだけでタイムラインでの見え方が変わる

## レシピ4: 撮影ゼロで喋り動画に図解を重ねる

**`/talking-head-recut`** — 人が喋っている動画の上に、
発言内容へ同期した図解カード・テロップ・ローワーサード・データコールアウト・
サイドパネル・PiP を自動で重ねる。**元の映像は下でそのまま流れる。**

喋りに合わせて数字がカウントアップし、固有名詞が出た瞬間に説明カードが差し込まれる。
ビジネス系 YouTube の手の込んだ編集がそのまま自動化されるイメージ。

```
/talking-head-recut を使ってください。
この動画に、話している内容へ同期した図解カードとテロップを重ねてください。
重要な数字はカウントアップで見せて、字幕は画面下部に配置。
デザインは frame.md に従ってください。
```

- **アバター生成の部分だけは HeyGen アカウントが必要。**
  すでに撮影してある自分の解説動画に図解を重ねる使い方ならアカウント不要
- キャンバスは 16:9 / 9:16 / 4:5 から選べる
- 字幕だけを付けたいなら `/talking-head-recut` ではなく
  **`/embedded-captions`** が正しい (デザインされた図解ではなく素の字幕)
- 講座コンテンツの解説パート、法人向けサービス紹介と相性がいい
- 撮影と編集という2大コストが同時に消える

⚠️ 発言との同期には文字起こしが必要。HeyGen TTS で音声を作った場合は
単語タイムスタンプが付いてくるのでこの工程が省ける。既存の映像に重ねる場合は
whisper-cpp が要る (macOS は `brew install whisper-cpp`)。

## レシピ5: GitHub の PR が60秒のレビュー動画になる

**`/pr-to-video`** — PR の URL を渡すと、そのコード変更を解説する
レビュー用動画を作る。タイトル、説明文、コードの差分、コミット履歴、
レビュアーの状況まで読み込んで、変更の規模に見合った尺に仕立てる。

**画面に出るコードはスクリーンショットではなく本物の差分。**
消える行が赤く畳まれ、追加された行が緑で着地する。

```
/pr-to-video
ここにPRのURLを貼る
このPRはレビュー待ちです。
60秒前後のレビュアー向けブリーフィング動画を、日本語ナレーションで作ってください。
```

- 入力形式は PR の URL、`owner/repo#N`、
  またはチェックアウト済みリポジトリで「このPR」
- 開発現場ではレビュー待ち時間を削るツール
- **法人提案のネタとしても筋がいい。** 開発チームを抱える会社に
  「御社のコードレビュー、動画で回せます」と具体物で見せられる。
  相手のリポジトリで実際に1本作ってデモするのが一番伝わる

## そのほかのワークフロー

上流には5レシピ以外もある:

| ワークフロー | 用途 |
|---|---|
| `/product-launch-video` | サイトURL・商品情報からプロモ動画。**商用URLの既定** |
| `/embedded-captions` | 既存の喋り動画に素の字幕だけを付ける |
| `/slideshow` | プレゼン・ピッチデッキ。出力は MP4 ではなく操作可能なデッキ |
| `/general-video` | 上のどれにも当てはまらない自由な構成。長尺・複数シーン・montage |
| `/remotion-to-hyperframes` | 既存 Remotion (React) を HyperFrames HTML に移植 |
| `/figma` | Figma のフレーム・ブランドトークン・コンポーネントを取り込む |
| `/changelog-video` | 週次 changelog の .md から定型の changelog 動画 |

**サイトから動画を作りたい場合、記事では `/website-to-video` と紹介されているが
実際のワークフロー名は `/product-launch-video`。** サイトのツアーや
ショーケースもここに入る。

---

## どれから試すか

**レシピ3の実績カードが最短。** 入力が一文で済む。

そして最初の1本は下手でいい。というより、
**下手な1本を出さないと修正指示の練習台が手に入らない。**
HyperFrames の本領は直しのループにあるので、
たたき台を出す速度がそのまま成長速度になる (→ [retake.md](retake.md))。
