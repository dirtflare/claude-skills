# ブランドを仕込む — `frame.md`

## なぜ必要か

AI が作った動画がどこか安っぽく見えるのは、品質が低いからではない。
エージェントがあなたのブランドを知らないので、毎回「それっぽい何か」を
**世界の平均値**で出してくるからだ。色もフォントも動き方も平均。だから既視感が出る。

Canva のテンプレートが没個性になるのと構造的に同じ現象で、
逆に言えば**ブランド情報を先に渡せば AI は驚くほど従順に守る。**
問題はセンスの有無ではなく、伝えるための書式がなかっただけ。

## ファイル名の落とし穴 (最重要)

上流の仕様はこの順で**最初に見つかった1つ**を読む:

```
frame.md  →  design.md  →  DESIGN.md
```

```bash
SPEC=$(ls frame.md design.md DESIGN.md 2>/dev/null | head -1)
```

**大文字の `FRAME.md` は探索対象に入っていない。**
プリセットが配布するテンプレートのファイル名が `FRAME.md` なので誤解しやすいが、
プロジェクトに置くときは**小文字の `frame.md` にリネームして採用する**のが正しい。

- Linux / CI: `FRAME.md` は完全に無視される
- macOS: ファイルシステムが大文字小文字を区別しないので偶然動く

つまり macOS で作って動いた気になり、Linux や CI に持っていった瞬間に
ブランドが外れる。**必ず小文字。**

`frame.md` が動画プロジェクトでは最優先。`design.md` は Web / 静的ページ向けの
同じ書式で、`frame.md` は同じものを「フレーム単位」で言い直したもの。

## ファイルの構造

**YAML フロントマター + Markdown 本文**で、2つの層は対等ではない。

- **フロントマターが正規の層** — `colors` / `typography` / `spacing` /
  `components` が機械可読の実値。**hex やフォント名は一字一句そのまま。**
  丸めたり発明したりしてはいけない
- **本文は文脈** — `##` セクション (Overview / The Frame / Composition Rules 等) が
  意図・使いどころ・トークンでは表せない制約を持つ。値ではなく判断材料として読む

## 作り方 3ルート

### ルート A: 自分のサイトから抽出する (サイトを持っている人)

手書きしなくていい。URL だけ差し替えてそのまま投げる:

```
https://あなたのサイト.com から僕のブランドの design.md を作ってください。
ライブのHTMLと、実際に読み込まれているCSSファイルを取得して、
色のhexコードとフォント名はCSSから一字一句そのまま抜き出すこと。
スクリーンショットから色を推測するのは禁止です。
フォントは代替候補ではなく、実際に読み込まれているものを報告してください。
サイトの実際の見出しを3〜5本読んで、そこから声とトーンのルールを導いてください。
中身は絞ってください。
役割と組み合わせ付きの色を4〜6個、文字の役割を2〜3個、
余白と角丸と影の値、そして「常に〜する」「絶対に〜しない」という形のルール。
トークンの羅列にはしないでください。
最後に、それぞれの色とフォントをCSSのどこで見つけたか出典を列挙して、
出典を示せない項目は削除してください。
```

このプロンプトの設計が優れているのは、
**推測を禁止し、実データから取らせ、最後に出典まで言わせる**点。
ハルシネーションを構造的に潰している。この作法は動画以外でも使い回せる。

出てきたら**主要な色を2〜3個スポイトツールで検証**して完了。

次に動画用へ拡張する:

```
この design.md を動画用の frame.md に拡張してください。
モーションの言語を追加してください:
要素がどう登場してどう消えるか、場面はカットで繋ぐのかフェードで繋ぐのか、
緩急の付け方、テンポ。
僕のブランドの性格に合ったものにしてください。
ファイル名は必ず小文字の frame.md にしてください。
```

落ち着いた教育系ブランドなのに動きだけギラギラ、という事故をここで防ぐ。

```
frame-presets の <プリセット名> を土台に僕の frame.md を作ってください。

フォントは <フォント名> にしてください。
それ以外のプリセットのルール (影・角丸・余白・動き方) はそのまま残してください。
プロジェクト直下に小文字の frame.md として置いてください。
```

プリセットを使うのは**必須ではない**。ゼロから書いても、
上流の `design-picker` (対話式のムードボード選択) で作っても等価。

### ルート C: サイトがない場合

普段の発信で使っている色コード・フォント名・口調のルールを文章で伝えて、
同じ書式でまとめてもらう。note と X が主戦場なら、
ヘッダー画像やサムネで使っている色をベースにすれば十分。

```
僕のブランドの frame.md を作ってください。
メインカラーは <#xxxxxx>、アクセントは <#xxxxxx>、背景は <#xxxxxx>。
フォントは <フォント名> 系。
口調は <例: 断定を避けず、丁寧だが硬すぎない。専門用語は必ず言い換える>。
動き方は <例: 落ち着いたフェード主体。派手なバウンドは使わない>。
役割付きの色4〜6個、文字の役割2〜3個、余白・角丸・影の値、
そして「常に〜する」「絶対に〜しない」のルールを含めてください。
ファイル名は小文字の frame.md にしてください。
```

## 効いているか確認する

ブランドリールを1本作らせるのが一番早い検証:

```
/hyperframes
僕の frame.md を渡します。
これを体現する20秒のブランドリールを1920x1080で作ってください。
ロゴとカラーパレットで始まり、タイポグラフィの見本を見せて、
このデザインシステムでUIカードを1枚組み立てて、最後はロゴで締める構成で。
すべての登場、退場、転換は frame.md のモーション言語に従ってください。
この動画は frame.md の映像化そのものです。
```

出てきた20秒を見れば、自分のブランドが動くとどうなるかが一発で分かる。
違和感があれば `frame.md` の該当箇所を直して作り直す。

## 運用

- 置き場所は**動画プロジェクトフォルダの直下**。以降そのフォルダで作る動画
  すべてに自動適用される
- **ブランドが複数あるならフォルダを分ける。** 同じフォルダに置くと混ざる
- `design.md` という書式は HeyGen の独自規格ではなく、AI デザインツール界で
  共通化しつつある形式。**動画以外の AI 制作物にも流用が効く汎用資産**
- 一度作れば以降すべての動画がブランドの制服を着て出てくる。
  この10分をやった人とやらなかった人で、3本目あたりから見た目が別物になる

## 上流の仕様を直接読む

このガイドは要約。一次情報はローカルに入っている:

```
.agents/skills/hyperframes-creative/references/design-spec.md      # 書式と解決順
.agents/skills/hyperframes-creative/references/video-composition.md # 適用の契約
.agents/skills/hyperframes-creative/references/design-picker.md     # 対話式の作成
.agents/skills/hyperframes-creative/references/house-style.md        # spec がない時の既定
```

`video-composition.md` の要点だけ先に言うと、
**design spec はブランドであってレイアウトではない。**
hex・フォント・Do/Don't には厳格に従い、画面の組み方は自由に決める。
また Web UI の不透明度そのままではなく、**動画に合った強度**で色を使う。
