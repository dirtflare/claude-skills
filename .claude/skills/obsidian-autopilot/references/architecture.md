# なぜ構造だけでは機能しないのか

## 観測された失敗モード

PKM / 第二の脳が放棄される理由として、実務者の記事に繰り返し現れるもの。
いずれも研究ではなく実践者の観察なので、断定ではなく傾向として扱う。

| 失敗モード | 内容 |
|---|---|
| **Collector's fallacy** | 集めること自体が有用に感じられる。だが手元にテキストがあることは、知識が増えたことを意味しない |
| **保守コストの破綻** | 「餌を与え続けなければならないシステム」になる。実務が忙しくなると、維持コストが、本来助けるはずだった仕事と競合して払えなくなる |
| **想起の摩擦** | Vault から引き出すより、ゼロから考え直す方が速い状態。こうなると誰も開かない |
| **蒸留されない** | 生のクリップが積み上がり、要点が抽出されないまま腐る |
| **IKEA 効果** | 自分で組んだ凝ったテンプレートとタグ体系を過大評価する。役に立っていなくても価値があるように感じる |

最後の 1 つが厄介で、**整えること自体が達成感を生む**ため、
機能していないことに気づきにくい。だから主観ではなく数字で測る必要がある
（`vault_stats.py`）。

## 構造の限界

Schema・テンプレート・Validator・命名規則は、どれも「どこに置くか」を決める。
これらは**置かれた後**の問題を解くが、次の 2 つは解かない。

1. そもそも書かれない（入力が人間の意志力に依存している）
2. 書いても思い出されない（想起が人間の記憶に依存している）

整った空の Vault は、散らかった Vault より使われない。
整っている分、汚すことに抵抗が生まれるからだ。

## 設計方針

自動化するのは**整理ではなく、入力・想起・押し出し**。
整理（分類・蒸留・昇格）は人間が判断すべきもので、
AI に任せると誤分類が静かに蓄積する。

```
人間が決める          自動化する
──────────            ──────────
何を残すか             入力を取り込む
何が重要か             関連を思い出す
どの判断を採用するか    期限と停止を突きつける
どの考えを中心に置くか  効果を測る
```

## 実装上の判断と根拠

### なぜ `UserPromptSubmit` に想起を載せたか

このフックは `additionalContext` を返せる。返した文字列は、
そのターンの Claude の文脈に入る。

つまり**ユーザーが検索しなくても、話題に関連する過去の自分の結論が
勝手に会話へ入ってくる**。これが「想起の摩擦」への直接的な答えになる。

他のフックでは文脈へ注入できないため、この位置以外に選択肢がない。

### なぜ `SessionEnd` を使わないか

記録を残すなら会話終了時が自然に見えるが、採用しなかった。

- `SessionEnd` のフックは既定で **1.5 秒のバジェット**を共有する
  （個別 `timeout` で最大 60 秒まで引き上げられる）
- 非同期処理が完了前に kill される不具合、そもそも発火しない不具合が報告されている

記録の取りこぼしは「自動記憶していない」という元の不満に直結するため、
確実に発火する `Stop` を使う。`Stop` は `last_assistant_message` を
直接渡してくれるので、transcript を解析する必要もない。

### なぜ全ての例外を握り潰すか

フックはユーザーのセッション内で毎回走る。
ここで例外を投げると、Vault の不整合が**Claude Code の操作そのものを壊す**。

第二の脳は、壊れたときに本体を道連れにしてはいけない。
インデックス破損・Vault 不在・壊れた JSON、いずれでも exit 0 を返して黙って諦める。

### なぜ CJK bigram + BM25 か

日本語は空白で単語を区切らないので、素朴な whitespace tokenize は機能しない。
形態素解析器（MeCab 等）は精度が高いが、外部依存と辞書が必要になる。

文字 bigram は辞書不要で、日本語の検索において実用的な精度が出る。
依存ゼロで動くことを優先した。

ただし bigram は「ている」「るか」のような**機能語で偶然一致する**。
対策を 3 段重ねている。

1. ひらがなのみの bigram はスコア寄与を 1/10 にする
2. 内容語（漢字・カタカナ・英数）が 1 つも一致しないものは落とす
3. 最高スコアに対する比率（既定 0.3）未満は落とす

3 の相対しきい値が効く。絶対スコアの閾値は Vault の規模で意味が変わるため、
「一番関連するものに比べて明らかに弱いものは出さない」方が安定する。

### なぜ希少語の 1 件一致を許すか

誤検出を抑えるには「2 語以上の一致」を要求したくなるが、
それだと `LTV` のような固有語の完全一致が落ちる。

ASCII 3 文字以上で、かつ出現文書数が 2 以下の語は、
1 回の一致でも強い信号として採用する。CJK bigram（長さ 2）は対象外。

## 想起に効くノートの書き方

インデックスはフィールドごとに重みを変えている。

| フィールド | 重み |
|---|---|
| タイトル | 4 |
| aliases | 4 |
| `## Use When` / `## Claim` / `## Decision` / `## What Changes If True` | 3 |
| 見出し | 2 |
| 本文 | 1 |

`## Use When` を重くしているのは、そこに**未来の検索意図が文章で書かれる**からだ。

> 料金プランを改定するとき。高単価商品の営業トークを作るとき。顧客が価格に反対したとき。

この一文があると、「年額プランの割引どうするか」と話しかけただけで
そのノートが浮上する。タイトルを分野名ではなく主張にするのも同じ理由。

## 関連する既存ツール

この実装は依存ゼロを優先したが、別の選択肢もある。

- **Smart Connections** — ローカル埋め込みモデルによる意味検索。API キー不要。
  bigram より意味的な近さを拾えるが、Obsidian 内で完結するため
  Claude Code の文脈へ自動注入はできない
- **Obsidian Local REST API** — `127.0.0.1:27124` で読み書き。
  見出し・ブロック・frontmatter 単位の部分更新ができる。Obsidian の起動が必要
- **Obsidian 公式 CLI** — move / rename で内部リンクを自動更新する。
  ファイル移動は必ずこちらを使う
- **Obsidian MCP サーバー群** — Claude から Vault を直接操作する。
  ファイル直読み型（Obsidian 不要）と REST API 依存型がある

併用して構わない。自動想起を Smart Connections の埋め込みに差し替えたい場合は、
`vault_search.search()` と同じ戻り値を返す関数に置き換えればフック側は変更不要。
