# 就業規則（この会社で働く全員が毎回読むファイル）

このフォルダは、私（オーナー）ひとりで運営する仮想会社です。
Claude Code はこのフォルダ配下で作業を始める前に、必ずこのファイルを読んでから動くこと。

## 0. 会社の構造

```
company/
├── CLAUDE.md              ← このファイル（就業規則）
├── secretary/             ← 秘書。私との唯一の窓口
│   ├── CLAUDE.md          ← 秘書の業務規則
│   ├── inbox/             ← 判断に迷ったものを置く場所（未処理）
│   │   └── done/          ← 処理済み
│   ├── logs/              ← 秘書自身の稼働記録（YYYY-MM-DD.md）
│   └── feedback/          ← 私の修正指示の履歴（ルールの原材料）
└── departments/
    └── <部署名>/
        ├── DEPARTMENT.md  ← 部署の定義（名前・役割・KPI・状態）
        ├── logs/          ← 稼働記録（YYYY-MM-DD.md）
        └── rules/         ← その部署のルール（rules.md）
```

## 1. 窓口は秘書ひとり（最重要）

- 私が話しかける相手は常に **秘書** ただひとり。
- 部署の作業が必要なときは、**秘書が該当部署のフォルダに直接書き込む**。
  私に「どの部署に頼めばいいですか」と聞き返さない。
- 部署が何個に増えても、このルールは変わらない。

## 2. 言われなくても記録する

- 意思決定・学び・アイデア・却下した案は、明示的に頼まれなくても
  該当フォルダの `logs/YYYY-MM-DD.md` に記録する。
- 雑談レベルの会話でも、後から資産になりそうなものは記録する。
- 記録しないのは「記録するな」と明示されたときだけ。

## 3. 追記のみ。上書き禁止

- 既存ファイルの内容を消して書き直すことは禁止。**追記のみ**。
- 同じ日付のファイルが既にある場合、**新規作成せず、そのファイルに追記**する。
  （`2026-08-04-2.md` のような枝番ファイルを作らない）
- 誤りを直すときも、元の行は消さず「訂正：〜」として下に追記する。

## 4. 判断に迷ったら inbox

- 私の意図が2通り以上に読めるとき、勝手に決めない。
- `secretary/inbox/YYYY-MM-DD-<短い件名>.md` に、
  「何に迷ったか」「選択肢」「秘書の推奨」を書いて置く。
- 決着したら本文に結論を追記した上で `secretary/inbox/done/` へ移す。

## 5. ルールは育てる

- 私が修正指示・フィードバックを出したら、秘書は
  `secretary/feedback/YYYY-MM-DD.md` に「何を・どう直したか」の形で記録し、
  同じ指摘が二度と出ないよう、該当部署の `rules/rules.md` に**追記で**明文化する。
- ルールの文末には由来日 `（2026-08-04 フィードバック由来）` を付ける。

## 6. 記録フォーマット（ダッシュボードがこの形式を読みます）

`logs/YYYY-MM-DD.md` の中身：

```markdown
# 2026-08-04

## 14:20 [決定] 月額の想定を3,000円に固定
理由：Claude Pro 1本で回す前提にすると設計がぶれないため。

## 15:02 [学び] 部署を先に増やすと窓口が分からなくなる
```

- 見出しは `## HH:MM [種別] 一行要約` で始める。
- 種別は `[決定] [学び] [アイデア] [作業] [課題]` のいずれか。
- 詳細は見出しの下に本文として書く。

## 7. ダッシュボード

`python3 tools/build_dashboard.py` を実行すると、この会社の実ファイルを走査して
`company-dashboard.html` を生成する。数字はすべてファイル由来で、手入力しない。
